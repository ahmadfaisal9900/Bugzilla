# Retrieval extension: design and preflight

Status: **implemented; awaiting user runs and review**. No study results have been generated by this work.

The project root and existing `origin` are authoritative. The Phase 3B store is `outputs/normalization/phase03b/run-20261022T023542Z-1182018/canonical.duckdb`; its verified manifest records 196,633 bugs and 419,458 comments. The seed-317 Firefox sample contains 3,000 distinct bugs. The separate Phase 4 overlay is `outputs/phase04/enrichment/cohort-8bb3150d29a598d8/api_enrichment.duckdb`; the base `field_changes` being empty does not imply the overlay has no events. The archive's field-level snapshot date is unknown.

The generated Phase 5 run is `outputs/benchmark/phase05/run-65c5be3381f66811`. On inspection, its original 175-row review queue had 175 pending rows; the separate UI signoff queue had 40 approvals and 24 corrections. There was no freeze marker. The six challenges are variants, not additional benchmark facts. These counts are an observation at this inspection, not an assertion that the reviewer has not completed their work. Genuine decisions must be audited and transferred, the global signoff completed, and freeze validated before test evaluation.

Existing code: `scripts/run_phase06_baselines.sh` exposes `m0`, `m1`, `m3`, and `bm25`, with `--model`, `--limit`, `--max-requests`, `--resume` and `--dry-run`. M0 is local Ollama closed-book; M1 uses a shared local model with lexical evidence; M3 uses a development-only audited SQL intent parser. No model ID is fixed by this runner; M0/M1 require an explicitly supplied installed model. No M4 implementation was located in `src/bugzilla_qa` or `scripts`. Do not infer that M4 exists or what it does without an actual implementation.

The new isolated code exports sampled metadata, public comments, explicitly recorded links and parsed status/resolution history, then builds SQLite FTS5. It excludes unknown/private comments and removes email-like strings and handles. This is not a complete personal-information scrub; indexes and exports remain ignored local files. History is a retrospective API observation, not proof that the system possessed that event in the past. The corpus is source-derived; no benchmark gold or review records are indexed. The full canonical DB hash is not recomputed: the tool checks the verified manifest identity and database size; the much smaller history database is hashed. A same-size change to the large database is therefore not detected by this fast check.

The extension implements a separate draft bank, source chunks with separate timestamps, FAISS cosine search, RRF, cross-encoder reranking, a simple parent-first retrieval heuristic, qrels, proxy metrics and a user-terminal orchestrator. It reuses the local Ollama adapter and existing family scorer. The model names in `configs/eval_extension.json` are proposed defaults; the resolved revision is recorded when the user first loads the model. No model was downloaded and no benchmark or index from this extension is frozen. F5 and natural wording require separate human review. The original M3 parser is development-only; no M4 adapter is possible without an actual M4 implementation. See `docs/EVAL_EXTENSION_STATUS.md` for limits and `docs/EVAL_EXTENSION_RUNBOOK.md` for commands.
