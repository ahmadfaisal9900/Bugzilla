# Retrieval extension metrics

Qrels join known source record IDs to indexed records. They are incomplete known-citation labels, not an exhaustive set of relevant passages. `retrieval_*_summary.json` reports Hit@5, known-citation Recall@5/10, reciprocal rank and nDCG@10, Precision@5 (fixed denominator five), and latency percentiles. The denominator for retrieval means is the number of questions with at least one indexed known citation in that method/family; unavailable citations are separately counted. F3 partition-wide counts and F6 evidence-scoped unknowns are not passage-enumeration tasks and are marked `NOT_APPLICABLE`, not zero. Duplicate chunks of one source record do not create extra relevant records.

The summary separates queries with and without explicit bug IDs. A paired cluster bootstrap compares hybrid versus lexical known-citation Hit@5 when enough paired clusters exist; it does not establish causal significance or human relevance. Hierarchical rows retain per-item stage-1 parent-bug recall. The SVG chart is an aggregate proxy, not a study conclusion. `tuning_dev.json` chooses RRF k from 30/60/90 using development known-citation Hit@5 only; no test gold is used for tuning. It does not tune chunk size, top-k or reranker candidates.

Optional local model predictions are scored by the existing `bugzilla_qa.evaluation.scoring` family-specific logic. F5 remains `NEEDS_HUMAN`, and model or parsing failures cannot earn abstention credit. M3 parser coverage and model failures are reported through the existing scoring output; compare supported tasks separately. There is no automated claim-grounding or citation-support adjudication, no exhaustive F5 relevance judgment, no answer-level bootstrap for the expanded bank, and no temporal-drift result. Missing metrics remain missing, not zero.
